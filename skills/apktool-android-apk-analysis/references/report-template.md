# Report template for an APK architecture review

## Required sections

```markdown
# APK Analysis: <package/version>

## Scope and authenticity
- Authorized app/artifact and user-provided source: ...
- Input filename, file size, SHA-256: ...
- Format: base APK / APK set / AAB / unknown
- Split and ABI completeness: ...
- Toolchain and platform: Windows/macOS/Linux, Java version, Apktool version, JADX version

## Preflight
- Installer/setup outcome: ...
- Tool paths verified: ...
- Missing utilities / blockers: ...

## Container inventory
- DEX files and code modules: ...
- resources.arsc, manifest and assets: ...
- ABI and .so libraries: ...
- ZIP risks or anomalies: ...
- Signing inspection (if authorized/available): ...

## Manifest + resource architecture
- Application subclass, launcher entrypoint, SDK levels: ...
- Components and processes: ...
- Permissions and intent filters: ...
- Resources/identifiers relevant to task: ...

## Code and call graph
| Role | Smali class/method descriptor | File:line | Caller/callee | Confidence |
|------|-------------------------------|-----------|---------------|------------|
| Example | Lcom/example/Foo;->onStart()V | smali/com/example/Foo.smali:12 | ... | static only |

## Selected behavior trace
- Trigger/input: ...
- Entry point: ...
- Intermediate calls/callbacks: ...
- Data transformations (inferred vs proven): ...
- Native/JNI involvement: ...
- Final output/observed behavior: ...

## Version portability
- Stable semantic anchors: ...
- Obfuscated/dex names that may change: ...
- Candidate alternatives/unknowns: ...

## Tests and evidence
- Commands run + exit code: ...
- Inventory and indexing results: ...
- Decompiled evidence: ...
- Runtime evidence: not tested / tested with criteria + result
- Gaps, contradictions and next tests: ...

## Optional authorized modification
- Patch purpose/diff: ...
- Build/sign verification: ...
- App behavior comparison: ...
- Rollback and expected data/signature impacts: ...
```

## Interpretation rubric

- **Observed:** verified via command output, static file content or instrumented test; cite file/path/line or sanitized log line.
- **Inferred:** supported by multiple concrete callers/descriptors but not yet proven in a running app.
- **Hypothesis:** plausible but unresolved; list what would falsify it.
- **Absent:** no matching evidence within explicitly enumerated input scope (e.g. only base APK), not necessarily absent from split/dynamic/runtime code.
- **Failure:** a command or test did not pass; record exact error and next diagnostic step.

Report limits of the source artifact. If a full app depends on dynamic modules or remote configuration, a single static base APK cannot settle all questions about runtime behavior.
